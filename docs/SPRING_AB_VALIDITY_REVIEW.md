# 015弹簧补偿A/B有效性复核（2026-11-15）

用户反馈feature/rl-motion31-supported015实机表现良好。本次复核结论：先前A/B不能用于判定015实机弹簧补偿有害，也不能据此建议取消补偿。

## 已确认

- 软件补偿没有重复加两次。测试adapter每5ms以零输入调用一次RLControlCompensateSpring取得附加项，再加到motor；电控普通015两次函数调用分别求诊断项与最终力矩，不把两次结果相加。
- 活动MuJoCo binary模型所有joint stiffness为0，两个tendon stiffness均0，没有plugin。没有明确实现本车真实被动弹簧及其力矩-构型关系。
- V4仍加NET拟合负载（含net_K和net_load）。例如L commonK19.9501Nm/rad、R differenceK16.5848Nm/rad；合同hardware_identified=false，不能断言这些就是本车弹簧、弹簧补偿后残差或已抵消弹簧的总负载。
- 原A/B只在V4 motor响应之后额外加015命令。实车普通015是PD→补偿→限矩→驱动器/机械响应；两者的动态插入位置不同。此前只核对补偿公式/左右映射并不足以认证整个执行链等价。

## 对0.30m结果的准确解释

额外补偿项在这个没有明确本车被动弹簧的模型里改变了总关节受力，平衡站高从约.343m降到.300m。这是当前模型/插入位置下的数值现象，不是015实机补偿失效的证据。

是否在物理意义上重复补偿/过补偿，目前无法确定，因为NET负载来源未分离。应区分“C补偿只加一次”（已确认）和“原拟合负载中是否已隐含等效作用”（未确认）。也不能简单反加一个负补偿当作已辨识弹簧来人为使仿真结果吻合。

## 处理

- 原run、结果和失败证据不重写，只将可解释范围收窄为原V4上的附加力矩敏感性试验。
- 不修改用户实机表现良好的015普通Motion补偿。
- 电控集成当前仍是38739bf旧tjb_recover比较版，本次没有新增实机补偿或修改固件。
- 下一轮若要回答实机有无补偿效果，应保留原015实际执行链，取得真实被动弹簧/驱动力矩/编码器几何的独立辨识，再明确NET是否为残差；没有这些证据不宣称仿真代表实车。

本复核未新增训练、物理积分或硬件操作。
